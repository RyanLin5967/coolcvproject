# Data platform, annotation, composition, and data correctness

Research date: 2026-09-17. This lane used seven Exa searches, primary documentation, live GitHub API reads, and direct inspection of RF-DETR's current `develop` criterion. Raw Exa responses are `raw/data_*.json`; inspected code is `raw/data_rfdetr_criterion.py`. Scope follows the user's update: quality first, no coding-time cutoff, with infrastructure/backend relevance considered alongside ML. No account creation, dataset downloads, or training runs were performed. All performance numbers below are proposed acceptance criteria, not achieved results.

## Adjacent products are a serious novelty filter

- **FiftyOne:** its open-source Brain has exact/near duplicate analysis and `compute_leaky_splits()`, including views that remove suspected leaks. It also documents group-aware split construction. A near-duplicate detector with a split warning is not novel. [Brain](https://docs.voxel51.com/brain/index.html), [Group splits](https://docs.voxel51.com/getting_started/annotation/02_setup_splits.html).
- **FiftyOne Enterprise:** snapshot versioning and diffs already exist; a prettier version diff is insufficient. [Dataset Versioning](https://docs.voxel51.com/enterprise/dataset_versioning.html).
- **Cleanlab/CleanVision:** image quality, duplicates, and object detection annotation errors are available, including wrong classes, wrong boxes, and missed objects. A generic label-error scorer should be rejected. [CleanVision](https://cleanlab.ai/blog/learn/cleanvision/), [Object detection errors](https://docs.cleanlab.ai/v2.6.4/tutorials/object_detection.html).
- **Encord:** multi-annotator consensus, annotation branches, ontology version history and restoration, and active-learning strategies are documented. A consensus labeler or schema history UI is a duplicate. [Consensus](https://docs.encord.com/platform-documentation/Annotate/annotate-projects/annotate-workflows-consensus), [Ontologies](https://docs.encord.com/platform-documentation/Annotate/annotate-ontologies/annotate-working-with-ontologies), [Active Learning](https://encord.com/blog/active-learning-computer-vision-guide/).
- **Datumaro:** format conversion, dataset comparison, class remapping, merge conflict reports, task-specific validation, and group completeness checks exist. These are useful dependencies and baselines. [Repository](https://github.com/open-edge-platform/datumaro), [Merge](https://open-edge-platform.github.io/datumaro/latest/docs/command-reference/merge.html), [Validate](https://open-edge-platform.github.io/datumaro/latest/docs/command-reference/validate.html).

## 1. Annotation-coverage-aware dataset composition

**Pitch:** Combine datasets without teaching the model that an unlabeled object is background. Preserve what was actually annotated all the way from imported data to training loss and evaluation.

**Real user and evidence.** A Roboflow user described two working detectors, stamps and coins: each source dataset contains the other object without its annotation. Straight concatenation therefore introduces contradictory negatives. This is a concrete first-person report from December 11, 2024, not proof of prevalence. [User report](https://discuss.roboflow.com/t/merging-two-separate-models-datasets-after-training/7951). RF-DETR issue #135 proposed per-sample annotated-class masks on April 9, 2025. A maintainer explicitly declined it as outside that work's scope; the closed issue must **not** be reported as implemented. [Issue and maintainer discussion](https://github.com/roboflow/rf-detr/issues/135).

**Current technical evidence.** Direct inspection of current `src/rfdetr/models/criterion.py`, particularly `loss_labels`, shows that the default IoU-aware BCE branch initializes negative weights over all query/class logits and sums the loss. No per-image annotation-coverage mask was evident in the inspected function. This establishes an implementation path and a bounded gap hypothesis, not a guarantee that no other Roboflow product or branch supports partial supervision. [Current criterion](https://github.com/roboflow/rf-detr/blob/develop/src/rfdetr/models/criterion.py).

**System and integration.** A composition service/CLI consumes immutable source manifests and ontology mappings. Each image/class records: exhaustively annotated, verified absent, positive but non-exhaustive, or unknown; unknown must remain the default when source coverage is not documented. It produces a canonical merged artifact plus a sidecar with provenance, coverage, unresolved taxonomy conflicts, and an explicit supported-consumer contract. A Roboflow adapter imports approved annotations/tags and creates a version; an external RF-DETR training adapter consumes the coverage sidecar. Do not imply stock hosted training accepts this new semantics. Export to a format that cannot preserve it should carry a loss-of-information report or refuse the unsafe operation.

**Small convincing slice.** Start with object detection, COCO, disjoint class coverage and the default RF-DETR loss only. Support image-level coverage, deterministic class remapping, preview of unknown regions/classes, and selective negative loss. Keep every known positive and all valid negative supervision. Handle encoder/auxiliary classification losses consistently. Do not claim a single global mask solves partial instances within one category; that needs region-level ignore or a separate method. Do not conflate dataset federation with privacy-preserving federated learning.

**Ambitious version.** Add many-source lineage, ontology hierarchies, label-policy versions, coverage-preserving crop/augmentation operators, streaming composition, content-addressed artifacts, and an audit showing exactly which source assertions produced each training target. The hard backend problem is retaining semantics across transformations and consumers, not storing another JSON file.

**Accessible data.** Construct class-partitioned training sources from a selected COCO subset, with all source removals recorded by the experiment controller. The learner sees only permitted labels and declared coverage. Keep a fully labeled independent test split. Add a real heterogeneous-label experiment using COCO/LVIS after checking class mapping and dataset terms. LVIS already distinguishes absent and non-exhaustive categories, and Detectron2 parses those fields. [Detectron2 LVIS loader](https://github.com/facebookresearch/detectron2/blob/main/detectron2/data/datasets/lvis.py). The live LVIS dataset site was not retrievable in this session; dataset download readiness is therefore not fully verified.

**Metrics and fair baselines.** Compare naïve concatenation, separate specialist models, pseudo-label completion at measured cost, selective negative masking, and an appropriate established partial-label baseline. Report macro AP, per-class recall/precision, fully annotated oracle upper bound, and inference/training cost. Use identical initialization, source images, training budget, and at least three seeds. Include complete-coverage data as a no-regression control and varying annotation coverage rates. Use a new source domain or dataset to test transfer; a simulated COCO split alone is insufficient for a headline claim. Gradient-level tests must verify unknown classes receive no forbidden negative signal while positives and verified negatives still work. Coverage loss through export must be detected deterministically.

**Demo.** Two projects work alone but miss each other's objects after naïve merging. A visual matrix exposes the contradictory negatives. Compile the same source data with coverage preserved; show the trained detector recovering both types on untouched footage, alongside full learning curves and the exact composition manifest.

**Attack and response.** This is not new ML research. Multi-dataset partial annotation has an extensive literature, and Detectron2 exposes federated-loss configuration. [2020 unified-label-space paper](https://arxiv.org/abs/2008.06614), [Detectron2 configuration](https://github.com/facebookresearch/detectron2/blob/main/detectron2/config/defaults.py). The distinction is a reliable data composition product plus an RF-DETR adapter and thorough evidence. A loss-mask patch alone is a small contribution; a pretty merger that silently invents coverage is invalid. Selective negatives may increase false positives because missing supervision is not recovered. Pseudo-labeling could beat it. The maintainer's prior scope decision reduces confidence in upstream acceptance; frame this as a standalone demonstrated extension, not a promised PR merge.

**Kill criteria.** Stop elevating it if gains disappear against pseudo-label completion at matched cost, if coverage cannot be represented honestly, or if the only demonstrated advantage depends on contrived label masking. Otherwise this is the data lane's strongest candidate.

## 2. Executable provenance and failure minimization for visual training data

**Pitch:** Given a bad training sample or unexplained evaluation result, trace exactly how bytes and annotations became tensors, identify the first semantic violation, and generate the smallest reproducible failing dataset.

**Real user.** RF-DETR/supervision maintainers, support engineers, and users integrating custom exporters or accelerated data pipelines. They need a failure artifact, not another aggregate health report.

**Evidence.** Recent fixes include hierarchical class mappings differing across splits, keypoint flips that failed to swap left/right identities, annotation paths overwriting colliding basenames, and COCO ID collisions. These establish real failure classes, but the cited historical defects are already fixed. [RF-DETR releases](https://github.com/roboflow/rf-detr/releases), [Supervision July 2026 fix](https://github.com/roboflow/supervision/commit/f173905c8bc6fab591bc3d3abdbf7ac7f5d93411), [Closed COCO ID issue](https://github.com/roboflow/supervision/issues/768). Current RF-DETR tests already cover numerous format cases; do not pitch the project as introducing basic testing. [Existing YOLO tests](https://github.com/roboflow/rf-detr/blob/develop/tests/datasets/test_yolo.py).

**Mechanism.** Define a small canonical sample representation with stable object IDs, coordinate conventions, category mapping, media digest, and split identity. Instrument adapters at decode, EXIF orientation, format import, resize/crop/flip, batch collation, and evaluator ingress. Record operator parameters and reproducible random state. A contract engine checks invariants appropriate to each operator; a reducer deletes unrelated samples, annotations, and transforms until the failure is minimal. The artifact includes the problematic images or license-safe synthetic equivalents, source/target overlays, the first failing operator, exact library versions, and a reproduction command.

**Backend depth.** Content-addressed artifacts, cached checkpoints of the pipeline, deterministic event ordering, bounded trace volume, plugin contracts, serialized failure manifests, reproducible workers, and CI triage. An on-demand trace should impose minimal overhead when disabled. The service can compare two library versions or CPU/GPU transform routes, but must distinguish allowable numeric drift from semantic changes.

**Narrow proof.** COCO↔YOLO detection plus crop/resize/flip, then one difficult task such as keypoint handedness or polygon rasterization. Build metamorphic properties: double flip preserves identity, invertible coordinate transforms round-trip within declared tolerance, class-order permutation leaves semantic results unchanged, format conversion preserves representable information, and the actual evaluator image IDs match the requested split. A transform that intentionally deletes out-of-frame boxes should be explicitly allowed. Pixel equality is wrong across lossy encoders or different interpolators unless exact equivalence is intended.

**Accessible corpus.** License-free generated scenes with known geometry; deliberately adversarial empty, boundary, sparse-category, nested-path, EXIF-rotated, small-object, and multi-instance cases; a small attributed COCO sample set. Historical commit pairs establish positive controls. New bugs should only be claimed after reproducing on a current version and checking open PRs.

**Validation.** Measure a predeclared mutation suite's detection rate, false positives on valid transformations, reproduction success in a clean container, failure reduction ratio, p95 triage runtime, and trace overhead. Replay fixed historical defects on the old version and verify the patched version passes. A useful release target is reproducible detection across several independent defect families and at least one independently verified new finding or meaningful reduction in maintainer reproduction time. Synthetic injected mutations must be labeled as such.

**Demo.** Drop a dataset/export pipeline into a CI job; it points to a class index shift in one split or a left/right keypoint inversion, shrinks thousands of images to one, and emits an executable artifact that reproduces without a GPU. A linked provenance view shows the sample through all stages.

**Attack and response.** Datumaro validates/compares/converts datasets; RF-DETR already has rich regression tests and loose-file/shard parity work. This survives only with **automated failure localization, reduction, and consumer-side semantic checks** across boundaries, not by wrapping existing validation in a UI. Robustness testing and Hypothesis are established techniques; the contribution is a reusable visual-data contract system plus high-quality adapters and genuine findings. There is no evidence Roboflow wants to adopt a new production provenance database, so ship a standalone CI/support tool first.

**Kill criteria.** Demote if it detects only invalid JSON, duplicates existing tests without better repros, or needs expensive instrumentation for every sample. This is likely the strongest infrastructure-facing data project.

## 3. Fleet annotation acquisition with replayable budget decisions

**Pitch:** Given many cameras but finite upload bandwidth and human labeling time, choose a useful set of independent events, account for the budget durably, and prove what the selection policy gained.

**Real user and integration.** Teams operating repeated visual conditions across cameras; the proposed consumer is an adapter around Inference/Workflows and Vision Events, producing Roboflow annotation batches. The need for representative selection is inferred from these platform surfaces, not a claim of a confirmed Roboflow fleet incident.

**Mechanism.** Cluster correlated frames into events or track episodes, estimate annotation cost, combine exploration with uncertainty/diversity, and allocate quotas across sites and rare slices. A durable reservation ledger prevents reconnect/retry storms from charging a budget twice. Selection records include model/policy versions, scores, candidate eligibility, selection probability where valid, and reasons for exclusion. Delayed human labels feed later acquisition rounds; they must not leak into the original selection decision. Offline edge workers can operate under bounded leases and reconcile with a central ledger.

**Why it might survive.** Roboflow already has collection caps, rules, event storage, and edge syncing; FiftyOne and Encord already offer smart sampling. The project must add measurable event-level acquisition quality **and** rigorously implemented distributed budget semantics. Replacing HTTP transport or storing metadata is not enough. Avoid promises of universal optimal acquisition or unbiased off-policy estimates for arbitrary deterministic selectors.

**Accessible proof.** Use MOT17 sequences for correlated-frame redundancy and object detection; split by sequence, never by adjacent frames. Use WILDS iWildCam for a separate camera/domain diversity experiment, clearly labeled as classification. [MOT17](https://motchallenge.net/data/MOT17/), [WILDS data](https://wilds.stanford.edu/datasets/), [Download instructions](https://wilds.stanford.edu/get_started/). Public dataset ground truth can simulate the annotator, but a small real timing study is needed before claiming labor savings. Gold labels remain hidden from the acquisition scorer until selected. Dataset terms and actual downloads need confirmation before implementation.

**Validation.** Plot detection AP or classification macro F1 versus reviewed minutes, annotation count, and uploaded bytes. Compare random frame selection, uniform temporal sampling, uncertainty sampling, diversity sampling, and event-level random selection. Measure duplicate-event rate, rare-slice recall, fairness of coverage across sites, label backlog, and end-to-end lag. At least three seeds, camera/sequence holdout, and multiple acquisition rounds are needed. Inject network partitions, duplicate events, delayed reviews, replay, and concurrent reservations; budget invariants must hold or documented bounded overruns must be measurable.

**Demo.** Replayed feeds show a limited daily annotation budget getting consumed by nearly identical frames under naïve rules. The proposed controller selects fewer independent events across different conditions; a replay slider exposes every decision and a learning curve shows whether those choices actually improve a model.

**Attack.** Events are hard to define; uncertainty can overselect blur or model-irrelevant novelty; diversity can overselect useless outliers; selection based on the deployed detector can miss confident systematic errors. Exploration and withheld-camera validation mitigate rather than eliminate these problems. Gains may be tiny relative to a simple frame interval plus per-camera reservoir. The systems scope is substantial, but a complicated allocator without better models is not a strong portfolio story.

**Decision.** Keep as a systems-rich conditional option. Require an early offline benchmark win over all simple baselines before building a fleet service. The absence of a coding-time cutoff does not justify building distributed machinery around an unproven scoring rule.

## 4. Annotation-policy migration planner — reserve

**User/use case:** A customer changes `road damage` into `pothole`, `longitudinal crack`, and other finer classes, or changes whether occluded objects should be labeled. A February 2026 Roboflow discussion is a concrete example; staff suggested deleting the incompatible source classes/images or updating them. [Discussion](https://discuss.roboflow.com/t/dataset-merge-guidance/11838).

**Project:** An executable policy with examples, explicit parent/child mappings, and assertions. Compare source and destination policy; classify changes as safe renames/merges, information-losing operations, or splits requiring review. Materialize a review queue and a reversible patch with provenance instead of guessing labels. Human reviewers adjudicate semantic ambiguity.

**MVP/demo:** COCO detection policies; replay a class split and show only the affected objects, unresolved examples, approved migration, and rollback. Use synthetic known migrations plus an independently annotated small road-damage subset. Measure affected-example retrieval precision/recall, false automatic edits, reviewer time, and exact rollback. This can be entirely CPU-first except optional model suggestions.

**Attack:** Encord already has versioned ontologies and restoration; Datumaro has remapping, merging and conflicts; Roboflow has class changes and annotation history. Natural-language instructions do not automatically become reliable machine semantics. Without demonstrated large reductions in review work on genuine policy changes, this is a schema editor. Best absorbed into candidate #1 rather than pitched independently.

## 5. Constraint-based leakage repair and evaluation contract — reserve

**User/use case:** A dataset mixes related video frames, original/augmented siblings, or duplicate imports across train and test. Roboflow's own benchmarking guide warns about contamination and similar environments producing optimistic results. [Benchmarking guide](https://github.com/roboflow/supervision/blob/develop/docs/how_to/benchmark_a_model.md).

**Project:** Keep declared groups and transformations together, infer candidate duplicate edges, distinguish hard provenance edges from soft similarity evidence, then solve a constrained repartitioning problem that preserves class/site coverage and minimizes changes. Emit a reviewable split plan, excluded/uncertain groups, and actual evaluator image-ID manifest. If rare classes or connected components make constraints impossible, explain infeasibility rather than silently deleting them.

**Data and validation:** MOT17, WILDS camera groups, controlled image transformations, and a second independent source dataset. Compare with FiftyOne leak detection, group random splitting, and stratified group splitting. Report edge precision/recall, residual known leaks, false group merges, retained data, class/site coverage, and evaluation behavior on a genuinely separate holdout. Do not call lower AP alone proof of better generalization. Never claim a certificate proves absence of all leakage or foundation-model pretraining contamination.

**Attack:** FiftyOne already detects leaky splits and removes leaks, with explicit group split recipes. Datumaro includes task-aware splitting. Repair optimization and auditable evaluation identity are incremental engineering, not a broad novelty claim. Keep as a useful module within candidate #2 or #1; not recommended as a flagship by itself.

## 6. Multi-model auto-label quality dashboard — rejected

The idea would combine foundation-model outputs, rank disagreements, and send them to review. Existing Roboflow Workflow auto-labeling explicitly supports ensembles and custom filtering. Cleanlab flags missing/wrong labels; Encord supports consensus; FiftyOne supports quality and mistake analysis. A well-executed domain-specific benchmark could be valuable, but the generic product has no defensible surviving angle here. Do not recommend it simply because SAM/VLM demos look impressive.

## 7. Universe-wide provenance/license trust score — rejected

The tempting idea is to map duplicate/derived images across Universe and score whether datasets are trustworthy. Universe exposes licenses and citations, and cross-dataset hashes can show overlap. However, overlap does not establish origin, ownership, chronological derivation, or legal permission. A complete crawler faces access, scale, changing URLs, and source-rights gaps; a polished score risks inventing certainty. A bounded source manifest for data the user actually controls is useful as part of #1/#2. A universal legal/trust oracle is not a good project.

## Practical selection advice

For a backend/infra application, prioritize **candidate #2**, with actual minimized reproductions and a compact CI integration. For the most distinctive data/ML story, choose **candidate #1** and publish honest controlled training results; its explicit Roboflow user and maintainer evidence make it more grounded than most generic data-quality proposals. Candidate #3 can be impressive systems work, but its statistical case must be established before investing in fleet infrastructure. No evidence in this research establishes a private Roboflow roadmap, endorsement, or intention to adopt any of these projects.
