# Independent design review

Reviewed September 17, 2026. This is a source/design review, not an implementation certification. No environment was installed and no training, numerical parity test, GPU benchmark, or cloud deployment was performed for this review. The reviewed baseline is RF-DETR **1.10.1**, commit `e3fc28795f2a4303069c6b72e80431e5ed716030`.

The project survives review as a bounded integration: explicit annotation-coverage declarations, a deterministic data artifact, selective classification supervision in RF-DETR, and a controlled experiment. It does not yet establish improved accuracy, upstream adoption, or a general solution to incomplete annotation. The architecture is sufficiently concrete to implement after the release-specific corrections below. Calling it perfect would obscure the execution gates that matter most.

## P0 gates: resolve before a long training run

### P0-1: Do not mix `develop` padding logic into release 1.10.1

The inspected release criterion does **not** have `_matched_valid_mask` or another ground-truth filler-validity mask. `num_boxes_for_targets` counts `len(target["labels"])`; `_get_matched_targets` and `loss_labels` use the supplied matched entries directly. Introducing padded filler targets without modifying the complete upstream path would change matching, the denominator, and box loss—not just classification.

**Required contract:** ground-truth padding is unsupported in this adapter. Reject it at configuration/input validation. Use ordinary variable-length targets. `PackedTargets` is a different feature: it concatenates tensor fields and reconstructs the original variable-length sample dictionaries without introducing filler boxes. It can remain enabled after a preservation test. Image padding in `NestedTensor` and dataset-length padding by repeating real samples are also separate concepts.

**Gate:** a real loader batch preserves each sample's `image_id`, labels, boxes, and coverage lookup through both packed and unpacked collation. Invalid target padding cannot silently enter the criterion. Source: [criterion](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/models/criterion.py#L485), [target packing](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/utilities/tensors.py#L496).

### P0-2: Preserve the exact criterion interface and whole-cell expression

The version-specific override is `loss_labels(outputs, targets, indices, num_boxes, log=True, matched_targets=None)`. Omitting `matched_targets` breaks inherited dispatch when the criterion shares its concatenated matched tensors between classification and box losses. A thin `forward` that attaches coverage must retain `num_boxes=None` and delegate the explicit override to `super().forward`.

The mask is `negative_allowed OR real_matched_positive`. Apply it to the entire unreduced IoU-aware BCE cell. The matched positive has a detached soft target and contains both terms of the BCE expression; merely zeroing negative weights is wrong. Preserve the denominator and group-DETR behavior. Inherited dispatch applies the overridden method to the final decoder output, every auxiliary decoder output, and encoder output; a final-output-only test is insufficient.

**Gate:** compare stock and adapter losses plus gradients on all-exhaustive targets. Include every classification branch actually used by the detection configuration, box/IoU losses, explicit denominator overrides, empty real target lists, multiple images/classes, training/evaluation group behavior, and nontrivial matching. Compare model gradients and one optimizer update on identical initialized models, not just a scalar loss value. Separately construct fixtures proving that forbidden semantic cells have zero direct classification gradient while known negatives and observed positives retain their stock behavior. Source: [classification expression](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/models/criterion.py#L534), [dispatch](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/models/criterion.py#L937).

### P0-3: Treat K semantic classes and K+1 output slots explicitly

The builder passes `args.num_classes + 1` to the detector and criterion. For the proposed two-pawn ontology, semantic model indices are `0` and `1`, and the extra output is index `2`. Preserve the extra slot's upstream negative supervision. An all-unknown image therefore does not imply zero total loss, zero parameter updates, or complete absence of indirect effects on its predictions.

The inference boundary also needs a contract. The pinned `PostProcess._select_topk` ranks **all** output slots. The pinned COCO evaluator maps model indices through `label2cat`, skipping labels that do not resolve to a category. Consequently, a successful evaluation run alone cannot prove the class mapping is correct.

**Gate:** assert the model/head/criterion dimensions; verify a round trip from every semantic key to source COCO ID to dense model index and back to evaluator ID. Use common upstream postprocessing across comparison arms. Record reserved-slot selections and mapping diagnostics. Reserved outputs must never be reassigned to a semantic class; an unmapped semantic output is an error. A synthetic highest-scoring reserved output must exercise the declared evaluator behavior. If later changing candidate selection to exclude the reserved slot before top-k, identify that as a separate common inference intervention and test it independently. Sources: [builders](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/models/lwdetr.py#L854), [top-k](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/models/postprocess.py#L121), [COCO label mapping](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/evaluation/coco_eval.py#L388).

### P0-4: Apply the correct ontology policy before making the common initial checkpoint

`reinitialize_detection_head` is a resize operation that tiles or truncates existing rows. Its name does not guarantee random initialization for a new ontology. A new last output row obtained by truncating a larger pretrained head is not necessarily the pretrained reserved row either.

**For a new ontology:** define a seeded initialization for the entire new `K+1` classification output matrix and its bias, including an explicit reserved-row policy. Apply it to the main `class_embed` and every two-stage `enc_out_class_embed` group. Preserve reusable backbone/box weights as declared. Perform the reset after pretrained weight loading and before creating optimizers or EMA, then write one common initialized detector state for all arms. Assert shapes and identical parameter digests when each arm begins.

**For the preferred same-ontology hosted base:** preserve the verified task-trained main and encoder heads. If class ordering differs, explicitly permute all affected rows and verify prediction equivalence. Do not apply the new-ontology reset after importing the seed-trained model. The hybrid addendum and [ROBOFLOW_INTEGRATION.md](ROBOFLOW_INTEGRATION.md) define its distinct data protocol; all continuation arms still begin with identical detector bytes and fresh optimizers.

EMA deserves an explicit choice: the pinned callback creates `AveragedModel(model=pl_module)` around the entire Lightning module, with buffer averaging enabled by default. A coverage table registered on the criterion is therefore also copied into the EMA object even if it is nonpersistent in `state_dict`. Define table ownership, device movement, checkpoint reconstruction, and digest verification. The simplest initial experiment can set `use_ema=False` consistently. If EMA is enabled, prove identical initial EMA/base detector weights and document which checkpoint family is evaluated. Sources: [head resize](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/models/lwdetr.py#L231), [checkpoint loading](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/models/weights.py#L427), [EMA setup](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/training/callbacks/ema.py#L141).

### P0-5: Prove the canonical bundle reaches the actual loader unchanged

The proposed canonical `splits/train.coco.json` layout is not the upstream Roboflow dataset layout. Materialize a versioned training view with `train/_annotations.coco.json`, `valid/_annotations.coco.json`, and resolved relative image paths, or explicitly supply an equivalent bounded data adapter. Do not set `dataset_file="coco"` and assume that arbitrary COCO JSON paths are discovered.

The upstream loader can filter parent categories and derives validation mapping from the train split. Emit a flat explicit ontology and identical category tables across splits. Assert the actual loader's `cat2label`/`label2cat` values. Global dense `image_id` values must survive source remapping, packing, device transfer, and all allowed transforms. A lookup-table row is valid only together with its bundle and ontology digests; range validity alone is insufficient.

The training view must contain only observed training labels and validation reference labels. Keep hidden training-label oracles and test labels out of the learner's view; the complete-reference arm has its own view. If validation loss is computed through the adapter, validation rows need explicit full-coverage semantics, not an accidental lookup into train rows. Sources: [Roboflow layout and mapping](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/datasets/coco.py#L1422), [data module](https://github.com/roboflow/rf-detr/blob/e3fc28795f2a4303069c6b72e80431e5ed716030/src/rfdetr/training/module_data.py#L199).

**Gate:** one real image with independently verified classes and boxes passes compile → training view → loader → transform → collate → model → criterion → prediction mapping. Include an image with no observed boxes, a sample whose number of boxes happens to equal K, and a shuffled batch. These catch metadata that is accidentally treated as per-box data.

### P0-6: Freeze the intervention and evaluation before reading outcome differences

The naive and aware arms must receive the same observed annotations, images, sampling, augmentation decisions, pretrained state, optimizer settings, update count, and evaluator. Fix the source-assignment/withholding seed before inspecting comparative model performance. Any image exclusions must be shared. Keep gradient accumulation at one for the first experiment so upstream accumulation semantics do not become a second variable.

The complete-label arm is a **reference**, not a mathematical upper bound. It has more labels, hence potentially different Hungarian matches and box-count normalization. Under a finite training budget it can underperform another arm without contradicting the mechanism. Likewise, masking can increase false positives. All three arms require the same evaluation ontology, checkpoint-selection policy, and fully annotated reference targets.

**Gate:** a saved experiment specification reconstructs the three views and their exact supervision difference. Final testing occurs after checkpoint and operating-threshold decisions. The report distinguishes correctness evidence from preliminary accuracy evidence and includes precision/recall and false positives alongside AP.

## P1 gates: resolve before claiming a robust result or distributable integration

| Concern | Strongest attack | Required evidence or bounded claim |
|---|---|---|
| Two-pawn chess benchmark | Small correlated scenes and easy visual classes can make a dramatic result fragile or cause saturation. | Report per-source image/box/class coverage counts; inspect scene groups and near duplicates before freezing splits; show baseline performance. Call it a mechanism pilot. |
| Pretraining and benchmark exposure | A held-out fine-tuning split does not prove absence from all pretraining/model-selection data. RF-DETR is already evaluated on Roboflow benchmark families. | Pin checkpoint provenance. State unresolved pretraining exposure. A later less-correlated external dataset is needed for broader generalization claims. |
| Annotation policy truth | A strict manifest can faithfully encode a wrong completeness claim. | Declarations identify their source and evidence; unknown is default. Do not infer exhaustive coverage from class lists, frequency, or a missing annotation. |
| `positive_only` | Masking removes unjustified negatives but does not provide missing boxes, solve ambiguous matches, or establish same-class partial-annotation accuracy. | Support the declared loss semantics while limiting the first effectiveness claim to withheld whole classes per image. |
| Augmentation defaults | Default resize/crop/backend behavior can differ from the intended allowed pipeline. | Pin the backend and actual transform graph; reject unsupported crop/multi-image/object-dropping transforms. Test retained sample identity and geometry. A prose list of allowed transforms is insufficient. |
| Resume/recovery | A weights file alone does not restore optimizer, scheduler, RNG, sample order, EMA, or coverage identity. | Separate initial detector state from full run checkpoints; verify identities at resume and record nonexact replay limits. Interrupted arms cannot silently enter an equal-budget comparison. |
| Coverage table lifetime | Registering a dataset-specific buffer can change checkpoints and EMA object state; a stale table can map valid IDs to the wrong coverage. | Declare persistent versus reconstructed state. Bind reconstruction to bundle and ontology hashes; test save/load and wrong-bundle rejection. |
| Compiler reproducibility | Canonical JSON does not settle semantic ordering, path normalization, source conflicts, finite coordinates, or concurrent publication. | Permuted-input determinism, contradictory-evidence rejection, split-collision detection, hash verification, and atomic-publication interruption tests. |
| Existing consumer compatibility | Ordinary COCO consumers can silently discard coverage. | Safe train entrypoint validates the bundle; plain export reports semantic loss. No claim that a normal hosted Roboflow Train upload enables this feature. |
| Cost/availability | GPU rate is not duration; retries/preemption may exceed a per-attempt timeout. | Measured smoke-test throughput, account budget/spend limits, one GPU at a time, persisted attempts/deadline, and retrieved checkpoints. No paid GPU starts during planning. |

## Setup review and reusable implementation choices

The updated account boundary is appropriate: **Roboflow is required** for source projects/versioned exports and the delivered inference integration, and hosted base training is preferred when trainable export is entitled and compatible. Its authenticated connector/orchestrator needs local credentials. The custom-loss worker needs only verified artifacts, not the Roboflow API key. Modal is the selected CUDA provider unless a suitable existing machine is used. GitHub and the selected public Hugging Face mirror require no new token for public downloads. Exa remains a research-only credential. No additional hosted database, queue, experiment-tracking account, or web authentication system is justified for this release. A paid Roboflow upgrade is unnecessary because the no-export fallback retains real platform integration.

Reusing the upstream model, matcher, box losses, Lightning loop, and evaluator minimizes the surface area, provided their pinned behaviors are verified. A small reviewed copy of the specific unreduced label-loss calculation is defensible because upstream returns a reduced scalar; preserve license attribution, link its exact source commit, and use stock numerical parity as the maintenance alarm. Do not copy the complete trainer or support multiple untested upstream versions through permissive introspection.

The initial architecture is already strong on explicit semantics, immutable bundles, train/test custody, bounded transforms, same-budget comparisons, and honest outcome reporting. The release-specific integration gates above are the work needed to turn that plan into evidence. Once those pass, a one-seed pilot is useful even if it finds no AP gain. Claiming a generally better detector or a ready-made Roboflow product feature would require substantially more evidence.

## Review disposition

- **Proceed to implementation:** compiler contract, strict RF-DETR 1.10.1 adapter, account/environment setup, and correctness fixtures.
- **Do not launch the long experiment yet:** P0 gates require executable evidence that does not exist during planning.
- **Do not promise the result:** improved accuracy, provider throughput, hosted checkpoint compatibility, and upstream acceptance remain hypotheses or compatibility checks.
- **Do not re-open permission prompts for ordinary work:** the review used ordinary tools under full access/approval-never, with no escalation request. Account authentication is a user login action, not permission to read public metadata.

## Addendum: Roboflow-first hybrid training review

The updated requirement makes Roboflow a required integration. The preferred design is **Roboflow hosted seed training → compatible weight export → three controlled Modal continuation arms → Roboflow deployment**. This is a valid experiment if weight export and import actually work. It measures selective supervision during continuation from a shared, task-trained model. It must not be described as running the custom loss inside hosted Roboflow Train.

### Freeze the export branch before expensive training

Confirm the account can obtain a trainable checkpoint for the selected RF-DETR architecture, that its license permits the proposed use, and that the pinned local model can load it with correct class names/output shapes and an audited list of missing/unexpected keys. An inference API, ONNX artifact, or hosted model ID is not automatically a resumable training checkpoint. Do not pay for hosted training on the assumption that raw export is available. Verify hosted preprocessing, generated images, and the exact training dataset version as well.

If trainable export is unavailable or incompatible, use the established stock initialization for the controlled Modal experiment. Still use Roboflow for the real source projects/versioned exports, a separately identified hosted naive baseline if hosted training is desired, and the final deployment integration. A hosted-versus-Modal comparison is operational context; different trainers, schedules, initializations, or hidden settings prevent interpreting its difference as the effect of coverage alone. Resolve and record this branch before constructing the final experimental views. Deployment upload itself remains a compatibility gate until an actual exported checkpoint and prediction round trip succeed.

### Exact seed-subset selection rule

Create a new protocol, `coverage-chess-hybrid-v1`, with seed `20260917`. Never overwrite the original 202-image, 480-visible/490-withheld pilot or reuse its counts for the hybrid.

1. Complete the image/scene audit and freeze the original train/validation/test membership or its one necessary group-level repair. Only the resulting **training** membership is eligible for the seed. Validation and final test never become training images.
2. Keep each audited near-duplicate/scene group intact. Define a group key as SHA-256 of its sorted original relative image paths serialized with the established canonical JSON convention. Singleton images are groups too.
3. Rank groups by `SHA256(UTF8('coverage-chess-hybrid-v1' + NUL + '20260917' + NUL + group_key))`, with group key as deterministic tie-break. Starting from the lowest rank, take the smallest prefix containing at least **40 images**. This is exactly 40 if groups are singletons; otherwise record the actual larger size. Do not split a group to force a round number.
4. Before any model training, require at least 10 seed images containing each target class; the remaining training set must contain at least 30 images with both target classes and 20 with neither. These are prespecified pilot viability checks, not statistical guarantees. If the fixed partition fails, stop and revise the data protocol explicitly; do not search random seeds using model performance. A very large scene group can make this tiny dataset unsuitable for the hybrid.
5. Train the hosted base on all reference pawn annotations of the selected seed images. Use the existing validation partition for hosted validation/checkpoint selection, with exact split assignments locked. The final test stays outside the seed project and every hosted training request. If the provider requires an additional test partition, satisfy it from the seed allocation under a documented fixed subdivision, not the final test; reissue the resulting counts and rerun the class-support checks on the actual seed-training subset before running.
6. Remove seed images from every continuation arm. Apply the existing alternating digest-ranked A/B assignment algorithm to the **remaining** training paths under the new hybrid version string. Compute fresh visible/withheld counts and support tables; do not assume the original 480/490 outcome. The coverage-aware and naive arms receive identical remaining partial labels; the complete-reference arm receives the remaining reference labels.

Upload a dedicated seed dataset/view containing only seed training labels and the allowed validation labels. Do not create it by uploading every fully annotated training image and trusting an undocumented filter or automatic split. Save the exported hosted version's complete image/label inventory and verify that no continuation image, near-duplicate seed group, or final-test image entered its training split. Disable generated dataset augmentations for the initial controlled version, as specified in the integration plan. Record online training augmentations separately; any subsequently introduced materialized seed derivatives remain excluded from continuation.

### Initialization and comparison corrections

An exported base trained on this exact two-pawn ontology changes the earlier new-ontology head-reset rule. **Preserve verified task-specific heads** rather than resetting them after hosted training. Assert the semantic order and every main/encoder head shape. If a remapping is needed, apply the same explicit permutation everywhere and test prediction equivalence. Create one imported base-state artifact, record whether it contains EMA or ordinary weights, and start all continuation arms with that identical state and fresh, identical optimizer/scheduler state. Do not resume one arm's hosted optimizer history while initializing the others from weights.

Evaluate the imported base before continuation using the same local evaluator. High starting accuracy may leave little measurable room for improvement; report that instead of selecting a deliberately weak base after looking at outcomes. Fix the hosted training/checkpoint policy before comparing continuation results. All continuation arms still share image order, augmentation, updates, and checkpoint-selection policy. The complete-reference arm remains context rather than an upper bound.

Publish both the shared seed annotation count and each arm's continuation annotation count. This hybrid uses more complete task labels than the original partial-only pilot, so their scores and annotation budgets are not interchangeable. The seed model must never train on the deliberately withheld labels of continuation images. Identical initialization controls the intervention comparison; it does not erase pretraining exposure or establish unseen-domain generalization.
